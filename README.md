# Лабораторна робота 2

## Призначення
Ця лабораторна робота є продовженням Лаби 1.  
У межах роботи для проєкту **«Менеджер занять»** додано графічний інтерфейс на **WPF** та підготовлено базову архітектуру для роботи через **інтерфейси** і **Dependency Injection**.

## Структура рішення
Рішення складається з 5 проєктів.
### 1) StudyManager.Storage
Містить **storage/data класи** та **enum**
- `SubjectData`
- `LessonData`
- `KnowledgeArea`
- `LessonType`
Storage-класи:
- не містять обчислюваних полів
- не зберігають посилання на пов’язані об’єкти
- зв’язок між заняттям і предметом реалізований через `SubjectId`
### 2) StudyManager.Services
Містить логіку доступу до даних
- `FakeStorage` —> штучне сховище з тестовими даними
- `StorageService` —> сервіс для отримання предметів і занять
- `IStorageService` —> інтерфейс сервісу для роботи через абстракцію
У Лабі 2 цей проєкт підготовлено для використання через **Dependency Injection**.
### 3) StudyManager.Presentation
Містить класи для представлення даних
- `SubjectViewModel`
- `LessonViewModel`
У цих класах реалізовано:
- обчислювані поля
- підготовку даних для відображення в UI
### 4) StudyManager.ConsoleApp
Консольний застосунок з Лаби 1, який збережено як попередню реалізацію логіки навігації та перегляду даних.
### 5) StudyManager.WpfApp
Новий WPF-проєкт, доданий у Лабі 2.
Тут реалізовано:
- `MainWindow` з `Frame` для навігації
- `SubjectsPage` —> сторінка списку предметів
- `SubjectDetailsPage` —> сторінка деталей предмета та його занять
- `LessonDetailsPage` —> сторінка деталей заняття

## Логіка роботи застосунку
Після запуску WPF-застосунку...
1. відкривається головне вікно `MainWindow`
2. у `Frame` завантажується сторінка `SubjectsPage`
3. користувач бачить список предметів
4. при виборі предмета відкривається `SubjectDetailsPage`
5. на сторінці предмета відображається загальна інформація та список занять
6. при виборі заняття відкривається `LessonDetailsPage`
7. між сторінками можна повертатися назад через навігацію

## Архітектурні особливості
У Лабі 2 підготовлено використання принципів
- **DIP (Dependency Inversion Principle)**
- **DI (Dependency Injection)**
- **IoC (Inversion of Control)**

Для цього:
- створено інтерфейс `IStorageService`
- `StorageService` реалізує цей інтерфейс
- WPF-застосунок підготовлений до роботи через DI-контейнер
