# Лабораторна робота 1. «Менеджер занять»

## Призначення
Це консольний застосунок для обліку **предметів** і **занять**, які належать до цих предметів.
У рамках Лаби 1 реалізовано базову структуру проєкту, штучне сховище даних та перегляд інформації в консолі.

## Структура рішення (Solution)
Рішення складається з 4 проєктів:

### 1) StudyManager.Storage
Містить **storage/data класи** (моделі збереження) та **enum**:
- `SubjectData` —> дані предмета (Id, назва, ECTS, сфера знань)
- `LessonData` —> дані заняття (Id, SubjectId, дата/час, тема, тип)
- `KnowledgeArea` —> enum для предмета
- `LessonType` —> enum для заняття

**Storage класи не містять обчислюваних полів** і не зберігають зв’язки як об’єктні посилання.
- `SubjectData` **не має колекції занять**
- `LessonData` не містить `SubjectData`, зв’язок з предметом реалізовано через `SubjectId`

### 2) StudyManager.Services
Містить штучне сховище та сервіс доступу:
- `FakeStorage` —> статичні колекції з реалістичними даними.
  - мінімум 3 предмети
  - мінімум 12 занять (10 для одного предмета і 2 для іншого)
- `StorageService` —> **єдиний** клас, через який інші проєкти отримують дані зі сховища  
  (тобто ConsoleApp не звертається до `FakeStorage` напряму)

### 3) StudyManager.Presentation
Містить класи для **відображення/взаємодії** та обчислювані поля:
- `LessonViewModel` —> додає обчислюване поле `Duration` (тривалість заняття)
- `SubjectViewModel` —> зберігає завантажені заняття та обчислює `TotalDuration` (сума тривалостей)

Також тут реалізовано **ліниве завантаження** занять.
- Спочатку показуємо предмети
- Заняття підтягуються тільки після вибору конкретного предмета (`LoadLessons(...)`)

### 4) StudyManager.ConsoleApp
Консольний інтерфейс.
1) Отримує список предметів через `StorageService`
2) Показує список предметів і пропонує вибрати номер
3) Після вибору показує деталі предмета і (lazy) підтягує його заняття
4) Показує список занять, дозволяє обрати заняття для перегляду деталей
5) Дозволяє повернутися назад до предметів або вийти з програми
