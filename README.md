## Лабораторна робота 4. Фінальний проєкт

### Призначення
Ця лабораторна робота є фінальним етапом розвитку проєкту **«Менеджер занять»**.  
У межах роботи реалізовано повнофункціональний багатошаровий застосунок з графічним інтерфейсом на **WPF**, побудований на основі **MVVM**, **IoC** та **Dependency Injection**.

У порівнянні з попередніми лабораторними роботами, у застосунок додано:
- повний **CRUD** для предметів і занять
- **пошук, фільтрацію та сортування**
- **реальне файлове сховище** замість штучного
- **асинхронну** роботу з даними
- індикатор завантаження та блокування UI під час виконання операцій

---

## Структура рішення (Solution)

### 1) `StudyManager.Storage` · DB Models
Містить моделі даних та перечислення:
- `SubjectData`
- `LessonData`
- `KnowledgeArea`
- `LessonType`

Особливості DB Models:
- не містять обчислюваних полів
- не містять об’єктних посилань на пов’язані сутності
- зв’язок між заняттям і предметом реалізований через `SubjectId`

---

### 2) `StudyManager.Repositories` · Repositories + File Storage
Рівень доступу до сховища даних. Повертає **DB Models**.

Основні компоненти:
- `ISubjectRepository`, `ILessonRepository`
- `SubjectRepository`, `LessonRepository`
- `JsonStorage`
- `StorageSnapshot`
- `SeedDataFactory`

Особливості:
- використовується **JSON-файл** як реальне сховище
- файл автоматично створюється при першому запуску
- при першому запуску виконується початкове заповнення даними
- сховище розміщується в каталозі:
  - `LocalAppData/StudyManager/Data/study-manager-storage.json`
- усі операції роботи зі сховищем реалізовані **асинхронно**
- для забезпечення цілісності доступ до файлу синхронізується через `SemaphoreSlim`

Репозиторії працюють через інтерфейси, що відповідає принципу **Dependency Inversion**.

---

### 3) `StudyManager.Services` · Services + DTO Models
Рівень сервісів, який забезпечує взаємодію між UI та репозиторіями.

#### DTO Models

**Subjects**
- `SubjectListItemDto` -> модель для списку предметів
- `SubjectDetailsDto` -> модель для сторінки деталей предмета
- `UpsertSubjectDto` -> модель для створення та оновлення предмета
- `SubjectEditDto` -> модель для редагування предмета

**Lessons**
- `LessonListItemDto` -> модель для списку занять
- `LessonDetailsDto` -> модель для сторінки деталей заняття
- `UpsertLessonDto` -> модель для створення та оновлення заняття
- `LessonEditDto` -> модель для редагування заняття

#### Services
- інтерфейси:
  - `ISubjectService`
  - `ILessonService`
- реалізації:
  - `SubjectService`
  - `LessonService`

Сервіси:
- отримують DB Models з репозиторіїв
- конвертують їх у DTO
- виконують валідацію вхідних даних
- формують обчислювані значення, зокрема:
  - `Duration` для заняття
  - `TotalDuration` для предмета
- забезпечують каскадне видалення занять при видаленні предмета

---

### 4) `StudyManager.WpfApp` · UI (WPF, MVVM)
Графічний застосунок реалізовано на **WPF** з використанням патерну **MVVM**.

#### Infrastructure
- `INavigationService`, `NavigationService` -> навігація між сторінками через `Frame` в одному головному вікні
- `RelayCommand` -> синхронні команди
- `AsyncRelayCommand` -> асинхронні команди для роботи з UI без блокування потоку

#### ViewModels
У папці `ViewModels` реалізовано логіку сторінок:
- `SubjectsViewModel`
- `SubjectDetailsViewModel`
- `LessonDetailsViewModel`

#### Pages
- `SubjectsPage` -> список предметів
- `SubjectDetailsPage` -> деталі предмета та список занять
- `LessonDetailsPage` -> деталі заняття

#### Особливості UI
- застосунок використовує **одне головне вікно**
- навігація відбувається через зміну сторінок
- під час виконання асинхронних операцій:
  - відображається `Loading...`
  - показується індикатор прогресу
  - взаємодія з UI блокується
- у `.xaml.cs` розміщено лише мінімально необхідну логіку:
  - `InitializeComponent()`
  - встановлення `DataContext`
  - обробка `Loaded` для асинхронного завантаження
  - окремі події подвійного кліку для навігації

## Реалізований функціонал

### Предмети
Реалізовано:
- перегляд списку предметів
- перегляд деталей предмета
- додавання предмета
- редагування предмета
- видалення предмета
- пошук предметів
- сортування предметів

Для списку предметів доступні:
- пошук за назвою та сферою знань
- сортування:
  - `Name A-Z`
  - `Name Z-A`
  - `ECTS Asc`
  - `ECTS Desc`

---

### Заняття
Реалізовано:
- перегляд списку занять для предмета
- перегляд деталей заняття
- додавання заняття
- редагування заняття
- видалення заняття
- пошук занять
- сортування занять

Для списку занять доступні:
- пошук за темою, типом та датою
- сортування:
  - `Date Desc`
  - `Date Asc`
  - `Topic A-Z`
  - `Topic Z-A`
  - `Duration Asc`
  - `Duration Desc`
  - `Type A-Z`
  - `Type Z-A`

---

## Асинхронність
Усі операції взаємодії зі сховищем реалізовано асинхронно:
- завантаження списків
- відкриття деталей
- створення
- оновлення
- видалення
- збереження в JSON

Завдяки цьому UI не заморожується під час роботи з даними.

---

## Dependency Injection / IoC
Для впровадження залежностей використовується `Microsoft.Extensions.DependencyInjection`.

Реєстрація залежностей виконується у `StudyManager.WpfApp/App.xaml.cs`.

Через IoC-контейнер реєструються:
- репозиторії
- сервіси
- навігаційний сервіс
- ViewModels
- Pages
- `MainWindow`

UI не створює сервіси вручну, а сервіси не створюють репозиторії вручну. Усі залежності надаються контейнером.

---

## Логіка роботи застосунку
1. Після запуску відкривається сторінка `SubjectsPage`
2. Користувач може:
   - переглядати список предметів
   - додавати предмет
   - видаляти предмет
   - шукати та сортувати предмети
   - перейти до деталей предмета
3. На сторінці `SubjectDetailsPage` користувач може:
   - переглядати всі дані предмета
   - редагувати предмет
   - переглядати список занять
   - додавати заняття
   - видаляти заняття
   - шукати та сортувати заняття
   - перейти до деталей заняття
4. На сторінці `LessonDetailsPage` користувач може:
   - переглядати всі дані заняття
   - редагувати заняття
5. Усі зміни зберігаються у файловому сховищі та залишаються після перезапуску застосунку

---

## Забезпечення цілісності даних
У застосунку реалізовано підтримку цілісності сховища:
- заняття не існує без предмета
- при видаленні предмета автоматично видаляються всі пов’язані з ним заняття
